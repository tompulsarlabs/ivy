# Routine eval, 2026-09-23

This is the A/B behind v10 ([tompulsarlabs/ivy#21](https://github.com/tompulsarlabs/ivy/pull/21)).
The baseline is the prompts the cloud triggers have run since 2026-08-24,
against `main`'s steering files. The candidate is the rewritten
`routines/*.md` prompts, against v10's. Every row, answer included, is in
the three `2026-09-23-*.jsonl` files next to this one, and
`scripts/eval-routines.py compare` reads them.

No case that passed in the baseline failed in the candidate. The
differences, all in the direction v10 intends:

- **Terse state rows** (`check-green-silent`, `failsafe-green-no-journal`,
  `failsafe-grey-journal`): every baseline run wrote a `signal_source` of
  361 to 1,120 characters. The candidate wrote one lookup name, as the
  playbook's example row shows. One candidate check run still put three
  commit titles into `green_by` (171 characters); that is the candidate's
  only failure.
- **`scout-stale-scan-blocker`**: a blocker persisting three days now
  leads the Top pick section. The old playbook left this ambiguous, and
  neither baseline run did it.
- **`scout-daily-cap`**: with five of six contracts already created, the
  candidate opens at most one. Both baseline runs opened more. In
  production `scripts/dispatch-lint.sh` refuses such a commit; the eval
  grades the decision before that gate.
- **`scout-runner-not-ticking`**: one baseline run named a single cause for
  a stale heartbeat instead of both.
- **`failsafe-ongoing-condition`** (change): both candidate runs moved the
  outage line's date, counts, and citation forward in place. One baseline
  run left the page untouched. The other appended a dated restatement and
  a `## Changelog` entry, which is how the page reached nine restatements.
- **`retro-collapse-sediment`** (change): the candidate retro collapses the
  restatements into one current-state line. The old retro had no such rule.

## Transition

Three runs fail:

- `scout-daily-cap`: the old scout prompt's own dispatch step opened two

  old failsafe prompt still added a `## Changelog` entry.

Pasting the `routines/*.md` prompts into the triggers soon after merge
closes these gaps.

The extra turns are reads of files the playbook points each routine at
(reads a run, baseline to candidate):

- failsafe, 23.3 to 31.8: `dispatch/failed/` for contracts that finished but
  were recorded as failed (0.7 to 2.8), and the memory pages it updates;
- check, 10.0 to 15.3: more of today's journal and the contracts under
  `dispatch/` before it chooses and records;
- scout, 21.9 to 28.8: today's contracts, counted before queueing, and each
  candidate's memory page;
- retro, 20.2 to 33.4: the week's journals, including every `## Check`.

Whether each read earns its cost is a question for the retro's
steering-file pass. These are eval runs: headless, read-only, and without
MCP. The number is a relative measure, not the triggers' bill.

## Checks corrected after reading answers

Every row above is graded with the final checks. The `confirmed` measure
was added after the runs; each run's value comes from the sandbox that run
left behind, and each measure the run took itself reproduced exactly.

- `d13b39f`: the two memory cases had passed on the baseline because
  headless `claude -p` denied every edit, so "no new restatement" held by
  default. Edit cases now run with edits accepted, and a run with a denied
  write is not scored.
- `c3993f9`: `check-blocker-nudge-cap` read `nudge_candidate`, where a
  correct answer explained itself in the blocker's words. It now reads the
  push text. No final row changes under this fix.
- `ab275e8`: `failsafe-grey-journal` failed a run that found the day grey,
  secured it, and reported the state it left (green). It now grades that
  the failsafe fired. This flips one candidate run. `scout-parked-repo`
  failed runs that stated the parking rule rather than broke it; that check
  is gone, and the pick and contract checks cover the rule. This flips two
  baseline runs, one candidate run, and one transition run.
- `ed3c2d6`: `failsafe-stale-claim` dropped an unrelated contract into a
  queue that the check's journal and the day's commits both called empty.
  A careful run flagged it instead of reopening it. The case now strands
  the review the runner really claimed that day, and every file tells the
  same story.
- `27034cd`: `failsafe-ongoing-condition` also counts `## Changelog`
  entries, where each failsafe logged its restatement a second time.
- `7055d40`: `failsafe-ongoing-condition` also asks for today's citation on
  the page. A baseline run that never touched the page had passed.

## Caveats

- Two reps per case is a smoke test. Most differences above are two runs
  wide (0/2 against 2/2) and all point the same way; the one-run
  differences (`check-green-silent`, `scout-runner-not-ticking`) are noise
  on their own.
- The eval grades decisions given the evidence, not tool use. The evidence
  file stands in for the GitHub MCP lookups, and commits and notifications
  are graded as the routine reports them. Only the two memory cases are
  graded on edits they really made.
- One model at its default effort. `--model` runs the same cases on another.
