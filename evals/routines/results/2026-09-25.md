# Routine eval, 2026-09-25

The A/B behind v10 ([tompulsarlabs/ivy#21](https://github.com/tompulsarlabs/ivy/pull/21)),
run a third time, after Ivy's second review of that PR. The review found
three gaps in the 2026-09-24 run:

- The runs were not confined. Each sandbox had a random name, but it sat
  beside the work directories whose transcripts are named by case and
  variant, and nothing but the CLI's default permissions kept a run from
  reading them.
- The memory checks counted words. A page whose outage account was deleted
  and replaced by unrelated text could pass.
- The headline numbers were for `6b59878`, not the playbook at the head.

This run closes all three. Every variant ran at `14d3685`, the head's
playbook, under the confined harness, with structural memory checks and two
new cases for the review's P1. No rule or check changed between committing
`14d3685` and scoring these runs; one check was corrected afterwards (see
"A check corrected after the run"). Every row, answer and diff included, is
in the `2026-09-25-*.jsonl` files next to this one, and
`scripts/eval-routines.py compare` reads any two. The 2026-09-24 write-up
stays as the record of the memory-rule wording experiments.

## Confinement

**Before this run.** Across the 565 transcripts of the earlier runs (14,509
tool calls), the model reached for a path outside its sandbox 235 times.
210 of those mistyped its own long sandbox path; the rest were other
mangled paths and two `Glob /`. The CLI's headless permissions refused every
one, so no run read a transcript or anything else that named its case or
variant. That rested on a default, though, so the harness no longer relies
on it (`4b3a413`):

- Each run gets its own temporary directory, never under the work
  directory, and it is deleted once the run is graded.
- The run passes `--restricted`, which confines the file tools to that
  directory and ignores every settings file. Restricted mode also skips the
  project CLAUDE.md; `--add-dir` of the sandbox restores it. A logging proxy
  on a real case sandbox showed the system prompt, messages, and tools byte
  for byte the same as an unrestricted run's.
- Restricted mode also keeps a machine's personal `~/.claude/CLAUDE.md` out.
  An unrestricted eval on the Mac would have loaded the gstack section the
  cloud triggers never see.
- The same proxy showed every run sending effort `high`, the CLI default:
  a `CLAUDE_EFFORT` in the environment does not reach a child run.
- `IVY_EVAL_LIVE=1 python3 scripts/eval-routines-test.py` runs two real
  runs that must read inside the sandbox, load CLAUDE.md, write in edit
  mode, and fail to read a transcript planted beside the sandbox.

**This run.** 145 transcripts, 3,674 tool calls. Every path a tool call
named, 3,158 of them, sat inside the run's own sandbox; nothing reached
outside, and the short sandbox path ended the typos.

### A check corrected after the run

`scout-runner-not-ticking`'s `both_causes` wanted "sleep" (or "asleep")
beside "launchd" in one blocker. Both candidate runs wrote "awake". Adding
"awake" alone would also have passed the baseline's scanner blocker, which
names the Mac and launchd but not the runner, so the corrected check
(`471336a`) also wants the runner, the heartbeat, or a tick in the same
line. Re-graded, it changes three rows and no baseline row: this run's two
candidate runs and the `6b59878` transition run of 2026-09-24, each from
fail to pass. The rows here keep the grades they were scored with; with the
correction the candidate passes 45 of 48 preserve runs.

## The green decision

Ivy's review found the failsafe could call a day grey that real work had
made green: when the broad searches miss a worker's PR, nothing sent the
routine to the PR the day's contracts point at, and nothing told a clean
zero from one that contradicts a contract's record. `45abc4d` adds (d) to
*Deciding green*: search for the PR behind each contract claimed today,
exactly. Lookups that disagree make the day unknown: alert, and the
failsafe still secures it with the journal.

Two new change cases replay the real grey 2026-09-23, with the build
contract that timed out after opening `tomgreen.ai` #67 (its output tail

## The memory rule

The memory checks now grade the paragraph, not word counts (`14d3685`). A
measure can count the paragraphs and list items that match every regex in
a list, and each memory case requires one paragraph that names the scanner
outage with its start (09-08), a current count, the right citations, and
what the outage blocks. The failsafe cases also refuse any new "N missed
windows" count, so a restatement in other words fails like one that says
"still dark". The collapsed-page case and the retro require exactly one
such paragraph, the retro's with one count. Rebuilt from their stored
diffs, the 2026-09-24 runs of these cases grade as they did then, and
`scripts/eval-routines-test.py` checks each case against the right edit
and five wrong ones on its real page.

| Case | baseline | candidate | transition |
|---|---|---|---|
| `failsafe-ongoing-condition` (the page as it stands, nine restatements) | 0/2 | 2/2 | 1/1 |
| `failsafe-ongoing-collapsed` (the page the retro leaves) | 0/2 | 1/2 | 0/1 |
| `retro-collapse-sediment` | 1/2 | 1/2 | 1/1 |

- On the cluttered page the candidate moved the latest restatement forward
  in place in both runs. At `f5eefba` the same wording did so in 1 of 4, so
  across both days it is 3 of 6: the wording helps, but not reliably.
- The misses on the collapsed page, candidate and transition alike, each
  added a `## Changelog` entry for the confirmation. The baseline added one
  in both runs.
- The retro miss did collapse the five restatements into one current-state
  paragraph, but it opened "**Open since 2026-09-08T15:45 CEST, last
  confirmed 2026-09-20: 23 missed windows …**" and never said what was
  open: neither the scanner nor `local-wip.json` appears. The check wants
  the paragraph to name its subject, since the scout adopts memory claims
  as they stand. The baseline's old retro prompt collapsed the page in one
  of its two runs.

## Caveats

- Two reps per case is a smoke test. A one-run difference is noise on its
  own.
- The eval grades decisions given the evidence, not tool use. The evidence
  file stands in for the GitHub MCP lookups, and commits and notifications
  are graded as the routine reports them. Only the three memory cases are
  graded on edits they really made.
- One model at its default effort. `--model` runs the same cases on
  another.

## Reproduce

```bash
python3 scripts/eval-routines.py run --label baseline --steering 2aa1829 --prompts live --reps 2
python3 scripts/eval-routines.py run --label candidate --steering 14d3685 --prompts repo --reps 2
python3 scripts/eval-routines.py run --label transition --steering 14d3685 --prompts live --reps 1
python3 scripts/eval-routines.py compare evals/routines/results/2026-09-25-baseline-2aa1829.jsonl evals/routines/results/2026-09-25-candidate-14d3685.jsonl
```

`grade` re-scores the saved answers with the checks as they are now, the
correction included.
